## 2026-08-08 - Mass Assignment & Enum Validation Vulnerability in In-Memory Models
**Vulnerability:** Lack of field filtering and missing enum validation in Model `create` / `update` functions. This allowed clients to perform mass assignment, overwrite system-managed properties (such as `id`, `createdAt`), or pass arbitrary invalid/malicious values to enum fields (`status`, `priority`).
**Learning:** In simple Node.js Express APIs using in-memory model structures (rather than full ORMs with structured schemas like Mongoose or Sequelize), update operations are often implemented via naive shallow copying (`{ ...tasks[index], ...data }`). This transfers all incoming request body parameters straight to the datastore. Adding a strict field whitelist combined with explicit enum parameter validation prevents unauthorized data injection.
**Prevention:** Always define an explicit whitelist of permissible parameters on the model level (e.g., `ALLOWED_FIELDS`). In `create` and `update` functions, iterate only through this list of whitelisted fields or explicitly deconstruct inputs. Additionally, perform robust enum validation check using strict `undefined` check (`!== undefined`) to ensure optional values are validated when present.
