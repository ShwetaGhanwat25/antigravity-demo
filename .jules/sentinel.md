## 2026-07-23 - Task Mass Assignment and Lack of Enum Validation
**Vulnerability:** The `Task.update` model-level function accepted the entire request body via standard spread (`...data`), leading to a mass assignment vulnerability. This allowed clients to modify sensitive, system-managed fields such as `id` and `createdAt`. Furthermore, both `create` and `update` methods lacked enum validation on `status` and `priority` fields.
**Learning:** Silently ignoring validation on internal database/model logic when handling external input or relying solely on controller-level checks can lead to unexpected vulnerabilities, such as setting invalid system states or over-writing immutable fields.
**Prevention:** Implement model-level strict whitelisting of allowed fields in `update` and enforce enum validation in both `create` and `update` using a "fail-fast" error-throwing mechanism. Throw errors with a `status` property of 400 to allow the centralized `errorHandler` middleware to propagate detailed client-side messages securely.
