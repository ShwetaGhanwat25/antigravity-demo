## 2026-07-29 - Task Mass Assignment and Lack of Enum Validation
**Vulnerability:** The application was vulnerable to mass assignment because updating a task using Object.assign or spread operator of the user-provided req.body allowed modifying sensitive metadata/fields (like id, createdAt, or any other un-whitelisted fields). In addition, tasks could be created or updated with invalid status and priority strings, potentially causing data corruption or unintended behavior.
**Learning:** In JavaScript/Node.js, using standard destructuring or spreading req.body without validation or a whitelist of allowed keys introduces mass assignment vulnerabilities. When throwing validation errors in an Express app with a custom errorHandler, throwing a generic Error is parsed as a 500 error unless an explicit status property of 400 is assigned to the Error object.
**Prevention:** Always implement a strict whitelist of editable keys in model update functions and strictly validate optional fields and enums (using strict undefined checks `!== undefined` to avoid falsy check bypasses) before persisting data. Assign a `status = 400` property to validation errors so the errorHandler exposes the actual message to clients instead of masking it as a 500 error.
