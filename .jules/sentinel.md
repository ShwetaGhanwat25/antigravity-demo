## 2026-07-18 - [Task Model Mass Assignment & Enum Validation]
**Vulnerability:** The task model's `update` function directly merged `req.body` into the existing task object without field whitelisting, allowing an attacker to modify sensitive fields like `id`, `createdAt`, or inject arbitrary properties. Additionally, there was no validation for `status` and `priority` enum values during task creation or update, which could lead to inconsistent data states.
**Learning:** Overwriting objects using the spread operator (`...`) with unsanitized inputs creates a mass assignment vulnerability. Validation of optional fields (like enums) must be handled strictly, distinguishing between `undefined` and other falsy/non-existent properties, and throwing explicit errors that map to correct HTTP status codes in the custom Express error handler.
**Prevention:** Whitelist properties explicitly in the model update/creation layers. Write input validation helper functions (e.g., checking values against allowed enums like `TaskStatus` and `TaskPriority`) and throw custom errors with `status = 400` properties so the Express `errorHandler` correctly reports the error to clients without exposing internal details.
