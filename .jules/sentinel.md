## 2026-08-12 - Mass Assignment and Lack of Enum Validation in Task Model
**Vulnerability:** The Task model lacked input validation and whitelisting on creation and updates. Specifically, tasks could be created with arbitrary `status` and `priority` values (not matching allowed enums). Furthermore, during task updates, the request body was merged in its entirety into the task object (`tasks[index] = { ...tasks[index], ...data }`), letting attackers overwrite sensitive fields like `id`, `createdAt`, or inject arbitrary fields.
**Learning:** Allowing bulk/mass updates of model properties without explicit attribute filtering/whitelisting invites security bypasses (like changing primary keys or creation dates). Additionally, skipping backend enum/type validation can contaminate database/in-memory states with invalid types.
**Prevention:** Always restrict update payloads to a strict whitelist of editable attributes (e.g., `title`, `description`, `status`, `priority`, and `assignedTo`). Implement strict enum checks on the backend, using strict `undefined` checks to prevent bypassed validation when falsy/null values are provided.
