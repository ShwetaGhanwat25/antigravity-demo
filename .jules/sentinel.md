## 2026-07-24 - Mass Assignment and Task Validation Bypass
**Vulnerability:** The `Task.update` method blindly merged properties from `req.body` into task objects. This allowed clients to perform mass assignment attacks, altering sensitive read-only fields like `id` and `createdAt` or adding arbitrary object keys. Furthermore, task `status` and `priority` did not have enum validation checks, letting clients set invalid status/priority strings (or even empty/null values) which polluted the database state.
**Learning:** When using in-memory arrays or ORMs without schema enforcement, properties passed in request bodies can overwrite internal record metadata if spread operators (`...data`) are used without whitelisting. Relying purely on controller-level destructuring can easily miss update endpoints, so model-level validation and whitelisting is needed.
**Prevention:** Always define an explicit whitelist of allowed update fields on the model. Use strict `!== undefined` checks for optional enums to catch invalid formats, empty strings, and null inputs. When validation fails, throw custom errors with an attached `status = 400` so that Express middleware can securely expose the validation error without leaking stack traces.
