## 2026-08-09 - Mass Assignment and Enum Bypass Vulnerability in Task Model
**Vulnerability:** The `update` function in `src/models/task.js` permitted arbitrary fields to be assigned directly to task objects. An attacker could exploit this mass assignment vulnerability to overwrite sensitive properties such as `id` or `createdAt` by including them in the HTTP request payload. Additionally, neither `create` nor `update` functions enforced validation for the `status` and `priority` enum fields, allowing tasks to accept arbitrary invalid values.
**Learning:** Volatile in-memory models using naive object spreading (`{ ...task, ...data }`) are highly vulnerable to mass assignment if parameters are not explicitly whitelisted. Furthermore, when enums are checked, strict `undefined` checks must be utilized instead of simple truthy/falsy checks to prevent bypassing validation via values like `null` or empty strings. Finally, thrown validation errors should attach a `status = 400` property so that the Express error handler middleware propagates the specific issue back to the client correctly rather than masking it as a 500 error.
**Prevention:** Always restrict fields during both creation and updates using an explicit whitelist. Implement fail-fast validation checks for enums inside the model layer before persistence, and throw custom bad-request errors when input constraints are violated.
