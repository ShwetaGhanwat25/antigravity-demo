## 2026-07-31 - Task Model Mass Assignment and Missing Enum Validation
**Vulnerability:** The task model in `src/models/task.js` was susceptible to mass assignment vulnerabilities, as the update function directly merged the unvalidated incoming payload (`data`) into the in-memory task database object. Additionally, there was no enum validation on the `status` and `priority` fields, allowing clients to inject arbitrary strings or bypass validations using values such as `null` or empty strings.
**Learning:** Overwriting properties via mass assignment happens when models accept unrestricted user input for updates instead of whitelisting explicitly allowed fields. Validation of enums should also use strict `!== undefined` checks instead of loose or truthy checks to prevent bad data from slipping in and causing database inconsistencies or application errors.
**Prevention:** Always implement strict field whitelisting on all update methods and perform explicit schema/enum validation on creation and updates using non-falsy validations where values like `null` should be rejected.
