## 2026-08-06 - [Mass Assignment and Validation Vulnerabilities in Task Models]
**Vulnerability:** A mass assignment vulnerability in task creation and update endpoints, combined with weak validation of task status/priority fields, allows attackers to inject arbitrary or invalid state values (e.g. status/priority) or overwrite non-modifiable metadata fields such as `id` and `createdAt`.
**Learning:** Over-reliance on simple object spread operators (`{ ...tasks[index], ...data }`) in models allows direct overwrites of protected properties if they are passed in request bodies. Furthermore, simple truthy checks for enums might bypass validation on values like empty strings or null.
**Prevention:** Whitelist allowed parameters for both task creation and updates. Implement a robust validation helper using strict `!== undefined` checks for enum properties (like status and priority) and immediately throw error objects decorated with a custom status property (e.g. `status = 400`) to propagate clean, validation-specific errors back to clients.
