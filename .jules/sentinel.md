# Sentinel Security Journal

## 2026-07-14 - Mass Assignment and Schema-less Update Vulnerabilities in Memory Models
**Vulnerability:** The in-memory data models (specifically the Task model) lack field whitelisting during update operations, allowing arbitrary fields (such as `id`, `createdAt`, and `updatedAt`) to be overwritten via client-supplied data in request bodies. Additionally, there was a total absence of validation on enum properties like `status` and `priority`, allowing client payloads to inject arbitrary string values.
**Learning:** In projects without a strict schema-enforcing database ORM (e.g. using simple volatile in-memory arrays), data updates using JavaScript spread/merge operators (`...data`) are highly susceptible to mass assignment vulnerabilities. If any validation fails at the model layer, we must 'Fail Fast' and throw validation errors with a status property (like `status = 400`) so that the express error handler middleware correctly bubbles the validation error response to the client instead of treating it as a standard 500 error.
**Prevention:** Always define an explicit whitelist of updatable attributes in the model layer and strictly filter input data before merging it with existing records. Perform strict undefined-checks on optional enums and throw structured validation errors with `status = 400` to guarantee strict domain logic enforcement and secure error propagation.
