## 2026-07-19 - Mass Assignment and Input Enum Validation in In-Memory Models
**Vulnerability:** Overwriting sensitive task fields (e.g., `id`, `createdAt`) due to lack of whitelisting in `update` functions, and silent acceptance of invalid statuses/priorities due to lack of model-level validation.
**Learning:** In-memory objects are prone to mass assignment when standard object spreading/merging (e.g., `{ ...task, ...data }`) is done without explicit field whitelisting. Furthermore, optional validation logic must use strict `undefined` checks (`!== undefined`) rather than truthy checks to prevent `null` or empty strings from bypassing constraints.
**Prevention:** Always define an explicit whitelist of allowed parameters and map them manually or filter them. Throw validation errors with custom `status` properties (e.g., `status = 400`) from models to fail fast and securely without exposing system errors, and ensure the custom express error handler is wired up to surface validation messages to the client.
