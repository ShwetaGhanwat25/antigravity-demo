## 2026-08-03 - Model-Level Mass Assignment and Input Integrity Mitigation
**Vulnerability:** The task model allowed unrestricted key-value updates via a generic spread operator (`...data`) during task updates. This enabled mass assignment, allowing users to modify critical metadata like `id` and `createdAt`, as well as inject arbitrary custom keys into in-memory task objects. In addition, task state and priority were not validated against enums, leading to invalid data state across endpoints.
**Learning:** Silently ignoring validation on updates or using unrestricted spread operators creates high-risk vulnerabilities where metadata integrity can be compromised. Throwing fast-failing validation errors (assigning `status = 400` to be handled by express error middleware) ensures invalid parameters are explicitly rejected, rather than accepted or masked as internal server errors.
**Prevention:** Always restrict accepted fields to a defined whitelist (e.g., `title`, `description`, `status`, `priority`, `assignedTo`) during creation and updates in the model or controller layer, and strictly validate enums using strict type/undefined checks rather than basic truthy/falsy checks.
