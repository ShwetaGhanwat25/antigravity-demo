## 2026-08-11 - Mass Assignment and Task Validation Bypass in Task Manager API
**Vulnerability:** The task update logic lacked field whitelisting, which created a mass assignment vulnerability. This allowed clients to overwrite internal and immutable model metadata such as `id` and `createdAt` via task creation or updates. Furthermore, there was no validation for status and priority enum values, allowing users to inject arbitrary status and priority values.
**Learning:** Standardizing input sanitation and validation purely at the controller or route layer can sometimes leave underlying model updates exposed, especially in dynamic JavaScript applications where destructuring or spreading request bodies (`...req.body`) is used. Model-level validation combined with explicit whitelisting is a robust way to implement defense-in-depth.
**Prevention:** Always define clear whitelists for permitted payload fields inside the model-level update/create functions. Enforce strict type and enum validation inside models to "fail fast", throwing errors that propagate to standard error-handling middlewares.
